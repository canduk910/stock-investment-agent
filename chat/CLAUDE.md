# chat/ — LLM 계층 (설명만 하는 챗봇)

이 계층의 존재 이유: **판정·숫자는 코드가 확정하고, LLM은 그 결과를 설명만 한다.** 상세 규칙은 `llm-safety-guide` 스킬.

- **★하이브리드 모델 = 용도별 2상수 단일 출처**(`chat/tools.py`). 코드 어디에도 모델 문자열을 산재시키지 않는다 — 바꿀 땐 이 상수만. 어느 호출이 어느 모델인지는 아래 표가 SSOT:
  | 호출 | 목적 | 상수 |
  |---|---|---|
  | `chat()`·`chat_stream()` 1차(tools)·2차(되먹임 답변) | 일반 대화(사용자 대면) | **`CHAT_MODEL`** = 상위 `gpt-5.6-terra` |
  | `structured_summary.request_json`(리포트·애널리스트·시황 요약 5 summarizer 공유) | 리포트·요약 생성 | **`REPORT_MODEL`** = 하위 `gpt-5.6-luna` |
  | `_reclassify_risk` | 안전 재분류(JSON) | **`REPORT_MODEL`** |
  | `intent_gen._gen_for_label` | 오프라인 학습데이터 생성 | **`REPORT_MODEL`** |
  대화 품질은 상위 terra, 스키마 강제 정형 작업은 하위 luna(비용·지연 절감). `chat.py`가 `CHAT_MODEL`·`REPORT_MODEL` 둘 다 import(대화 vs 재분류).
- **★모델별 필수 파라미터 = `CHAT_MODEL_PARAMS`(terra용)·`REPORT_MODEL_PARAMS`(luna용)(단일 출처, 매 `create()`에 병합)**. terra·luna **둘 다 추론형**이라 chat/completions에서 **function tools를 쓰려면 `reasoning_effort='none'`가 필수**(미지정 시 400 `Function tools with reasoning_effort are not supported`, 값은 현재 둘 다 `none`으로 동일). 또 이 계열은 구형 `max_tokens`/`temperature`를 안 받는다(앱은 안 넘김). `chat.py::_create_with_retry`가 `{**CHAT_MODEL_PARAMS, **kwargs}`로 병합(대화 경로·스트리밍 포함), `structured_summary`·`_reclassify_risk`·`intent_gen`은 `**REPORT_MODEL_PARAMS` 전달. **어느 한 모델을 비추론형(gpt-4o 등)으로 바꾸면 그 모델의 PARAMS를 `{}`로 비운다.**
- **위험 차단 = 2층 방어**(오탐 과다 완화). ①**결정적 키워드 정규식(`guardrail_label`)** = 하드블록(안전 하한선) — 단정예측/내부정보/시세조종/과도위험 4유형은 **LLM 미호출**로 즉시 차단(거절이 아니라 위험 환기 + 분산 안내로 방향 전환). ②정규식 미매치인데 **ML이 risk_guardrail로 분류**하면(오탐 가능) `chat.py::_reclassify_risk`가 **REPORT_MODEL(luna)로 2차 재분류**(`{block:bool}`) — 오탐이면 **정상 답변으로 진행(구제)**, 위험 확정이면 차단. 재분류 전체 실패는 재시도 후 **보수적 차단**(안전 우선, 드묾). LLM은 '차단 대상 여부'만 분류(자문·설명은 본 답변 LLM). 차단 판단은 `chat()`·`chat_stream()` 공통. **api/chat 라우트의 `live_judgement` 스킵은 `guardrail_label`(결정적)일 때만** — ML-risk는 재분류로 허용될 수 있어 국면 필요. **잔고·손익·포트폴리오 조회가 risk로 오분류돼 하드블록되던 문제를 이 2층 구조 + 데이터셋 보강으로 해소**(실측: "내 잔고 확인해줄래?" 개선 전 차단 → 후 정상).
- **인텐트 6분류 = ML 사전분류.** `intent_gen.py`가 REPORT_MODEL(luna)로 [질문→라벨] 균형 데이터(`data/intent_dataset.tsv`)를 생성 → `intent_train.py`가 `TfidfVectorizer(char_wb,(2,4))+LogisticRegression`으로 학습 → `chat/models/intent_clf.joblib`. 한글은 형태소분석기 없이 char n-gram으로 처리. 재생성/재학습해도 파이프라인 정의는 불변. **ML 정확도는 비결정적** → 단위 테스트는 인터페이스·가드레일만 고정하고 정확도는 단정하지 않는다. **단, 정당 조회의 risk 오탐은 안전 이슈**(하드블록) → `test_intent.py`가 `data/intent_dataset.tsv`를 즉석 학습해 큐레이션 정당 질의(잔고·손익·포트폴리오·추가편입)가 `!= risk_guardrail`임을 검증(데이터셋 품질, tfidf+lbfgs 결정적). 오분류 표현은 정답 라벨(portfolio_advice 등)로 데이터셋 보강 후 재학습(`uv run python -m chat.intent_train`, 모델 커밋). 비차단 라벨끼리(general_qa↔stock_analysis) 오분류는 안전 무관(LLM이 tool_choice로 결정).
- **인텐트 → 네비게이션 패널 결정적 라우팅(최초 설계 반영)** — `chat/intent_panel.py`: **인자 없는 3개 라벨**만 패널로 매핑(`macro_view→show_macro_dashboard`·`watchlist_mgmt→show_watchlist`·`portfolio_advice→show_balance`). `chat()`·`chat_stream()`이 `intent=classify()` 1회 계산 후 `merge_intent_panel(intent, popups)`로 **인텐트 패널을 popups 맨 앞에 주입(+LLM 중복 dedup)** → 프론트가 `popups[0]`로 전환하므로 **인텐트가 패널을 권위적으로 결정**(폴백에도 적용). ticker 필요한 종목리포트(`stock_analysis`/`analyst_report`)·args 필요한 편집(`manage_watchlist`)은 인텐트가 인자를 못 뽑아 **LLM function calling 병행**(매핑 0). **안전**: 편집·매매 패널은 절대 매핑 안 함(오분류가 편집/주문 유발 0)·가드레일 선차단 불변·팝업 계약/`popupRouter` SSOT 재사용(프론트 변경 0). 값(툴명)이 표시 툴·CONTENT_TOOLS 아님을 테스트로 잠금. **★예외(회귀 수정)**: LLM 이 **편집 확인 카드 `manage_watchlist`(사용자 [확인] 필요한 write 액션, `_ACTION_PANELS`)** 를 냈으면 인텐트 네비 패널을 주입하지 않는다(LLM popups 순서 보존) — 안 그러면 "관심종목 추가" 가 `watchlist_mgmt`→`show_watchlist`(목록)를 `popups[0]`에 밀어넣어 **확인 카드가 안 뜨는** 회귀 발생. 조회/네비 패널 충돌 시 인텐트 우선은 유지.
- **비유명 종목 macro_view 오분류 수정 = 종목명 gazetteer override + 데이터 균형(2-Layer)**: 유명주("삼성전자 어때?")는 종목리포트로 가는데 비유명 KRX주("롯데렌탈/에스피지/클래시스 어때?")가 시장 국면(macro_view) 패널로 새던 버그. 원인 = 학습데이터 유명주 편중 + 바로 "{종목명} 어때?" 구조가 stock_analysis 에 전무 → char n-gram 이 짧은 "어때?"를 macro 신호로 학습. **Layer A(결정적 pre-gate `chat/stock_gazetteer.py`)**: KRX 마스터(`collectors.stock_master.load_stock_master`·`.cache` 재사용·in-process 1회 캐시)의 개별 종목명(len≥3·ETF/인덱스/인버스 제외·긴이름 우선)이 **질문의 부분문자열(name⊆query)**이면 반환(`query_names_a_stock`). `intent.py::classify()`가 ML 예측 뒤 **`label=="macro_view"` 일 때만**(단락평가) 매치 시 `stock_analysis`로 재분류(가드레일 선차단 뒤·유효성 검증 앞·gazetteer 예외는 graceful로 macro 유지). **★override 타깃이 stock_analysis 인 이유**: `INTENT_PANEL`에 매핑이 없어(macro/watchlist/portfolio 3종만) `merge_intent_panel`이 popups 를 안 건드려 LLM 의 `show_stock_report`(ticker 포함)가 생존 — 잘못된 macro 주입만 제거(최소·안전). **name⊆query 방향**인 이유: 반대(query⊆name, `search_stocks` 방식)는 "코스피"가 "KODEX 코스피200"의 부분문자열이라 시장질문을 오탐. **Layer B(데이터 균형·재학습)**: `data/intent_dataset.tsv` +53행 후 `uv run python -m chat.intent_train`(오프라인·OpenAI 미호출·joblib 커밋). **★함정(적대적 검증이 잡음)**: stock "어때?" 보강이 짧은 조회형을 stock 으로 끌어당겨 **매크로(FX/원자재/통화)·포트폴리오 질문이 stock 으로 새는 역방향 회귀**(결정적 패널 라우팅 상실) 유발 → **영향 라벨 전부에 동일 짧은형 보강**(macro: 지수/시장+FX/원자재/금리/인플레+통화명/외래어침체/해외지수, portfolio: 짧은 조회형)으로 해소(모델이 접미사 아닌 **주어**로 판정). **아키텍처**: gazetteer=KRX len≥3 **결정적 보장** / 데이터 균형=macro·portfolio **누수 방지**. 외국주(테슬라)·2글자주(심텍)는 gazetteer 미대상 → **best-effort**(baseline 도 macro 였음·회귀 아님). **안전**: 매매 API 0·판정=순수 문자열 매칭(LLM/확률/랜덤 0)·guardrail 선차단 불변·override 는 macro_view 예측일 때만(종목명 든 watchlist/portfolio 오발 0). 테스트: `test_stock_gazetteer.py`(gazetteer 순수) + `test_intent.py`(override 유닛·`test_krx_stock_queries_route_to_stock_analysis`[classify 통합·gazetteer 보장]·`test_macro/portfolio_queries_do_not_leak_to_stock_analysis`[데이터 품질 잠금·회귀 방지]).
- **포트폴리오 상담 활성(코드 근거 자문)**: `build_prompt` 블록 ⑦ [포트폴리오 상담] — 잔고 스냅샷 근거 집중도·비중·손익 분석 + 국면 권장 현금비중 대비 조정 방향 + **추가편입 후보**(관심종목·분산·국면 관점, 근거 동반) + 국면·분산 부족 특성/**새 종목 아이디어**(방향 제안, 특정 종목 단정·구체 수치 날조 금지). ④/⑦ 완화로 후보를 actionable 제시 허용. **국면은 현금비중만 관리**(항목3 — `single_cap`/`per_max`/`pbr_max` 게이트 폐기, 종목별 진입 커트로 판정하지 않음). **불변**: ⑤ 단정 금지·**내부정보/시세조종 거부·수익 보장 금지**(재분류 backstop)·면책·과열 국면(현금비중 높음) 규율.
- **목표가 추천(에이전트) + 매수/매도 분리**: `manage_watchlist` set_target 이 `target_price`(매수)·`sell_target_price`(매도) 둘 다 수용(최소 1개, 프론트 popupRouter 검증). `build_prompt` **⑨ [목표가 추천]** 블록 — 사용자가 목표가 추천을 원하면 **애널리스트 목표주가 우선 인용("리포트에 따르면")→52주 고저·현재가 위치→현재/자기평균 PER** 순으로 **매수/매도 참고 범위**(X~Y원) 제시 후, 반영 원하면 `manage_watchlist(set_target, target_price, sell_target_price)`로 **제안**(확인 카드에서 사용자 [확인]—자동 저장·자동 매매 없음). **불변**: 단일 확정수치·"반드시 오른다" 금지, 스냅샷/리포트 인용만(수치 날조 금지), 상태 판정(reached/near/far)은 코드, 면책. `view_context._stock_context` 가 추천 근거(애널리스트 목표주가·**52주 고/저 원값**·PER)를 스냅샷에 싣고, `_watchlist_context` 는 **매수·매도 목표가/상태 둘 다** 인용.
- **기준표는 자동 생성**(`build_prompt.py::build_criteria_text`). `THRESHOLDS`·`INDICATOR_LABELS`·`VIX_PANIC`을 import해 만든다 — 임계값 숫자를 프롬프트에 하드코딩하면 3중 일관성이 깨진다. 시스템 프롬프트 필수 6블록(역할·판정출처고정·기준표+judgement·REGIME_PARAMS·설명지침·팝업규칙)과 면책 고지 포함. `judgement`는 매 호출 최신값 주입.
- **답변 서식 = 표·다이어그램 기본 곁들임(`build_prompt` ⑩ [답변 서식 — 표·다이어그램(기본 곁들임)])**: 봇 답변은 프론트가 `react-markdown`+`remark-gfm`(GFM 표)와 **mermaid** 코드블록을 렌더한다 → 프롬프트가 LLM에게 **비교·나열은 마크다운 표(GFM `| 열 | 열 |`)**, **관계·흐름·구성비·추세(포트폴리오 비중·국면 판정 흐름·의사결정 단계·지표 간 관계)는 ```mermaid 다이어그램(pie·flowchart)**으로 정리하도록 유도. **★기본 곁들임(사용자 결정)**: "그림을 곁들여" 같은 요청어가 없어도 **주제가 적합하면 시각 자료를 먼저 제시**한다("~해도 된다"는 선택적 표현에서 전환). **단 단순 용어 정의·짧은 사실 확인·한두 문장 답변엔 억지로 넣지 않는다**(도형을 위한 도형 금지 — 남용/희석 방지). **불변(⑤ 재확인)**: 표·다이어그램에 넣는 수치도 **판정 결과·기준표·조회 스냅샷·리포트 요약에 있는 값만**(값 없으면 도형·표 지어내지 말고 텍스트), **판정 주체는 코드**(도형으로 표현해도 에이전트 매수/매도 판정 아님)·"반드시 오른다/수익 보장" 단정 금지·면책 유지, 시각 자료엔 항상 텍스트 설명 곁들임. 잠금 테스트 `test_build_prompt::test_prompt_encourages_table_and_diagram_formatting`(마크다운 표·mermaid·다이어그램 문구)·`test_prompt_format_block_reaffirms_no_fabrication_and_code_judgement`("판정 주체는 코드"·"지어내"·"면책")·**`test_prompt_makes_visuals_default_when_fitting`**("기본"·"요청"[하지 않아도]·"억지로"[부적합 시 배제]). **라이브 실증**: "방어주와 성장주 차이·투자 판단 흐름 설명해줘"(서식 요청어 없음)→표+flowchart 자동 / "PER이 뭐야? 한 줄로"→60자 텍스트(그림 없음). f-string 이라 ```mermaid 코드펜스 삽입 시 중괄호 리터럴만 `{{`/`}}` 주의(현재 블록엔 중괄호 없음).
- **세션은 서버 인메모리**(`session.py`의 `SESSIONS`, 슬라이딩 윈도우 8). 시스템 프롬프트는 매 호출 재주입(누적 X → 국면 변경 자동 반영), tool 메시지는 히스토리에 미누적. 휘발성(서버 재시작 시 손실 — 클라우드 전환 시 DynamoDB/Redis).

- **★chat()/chat_stream() 공유 헬퍼(리팩토링 2026-07-29·행동 보존)**: 두 경로가 각자 들고 있던 프리앰블·에필로그를 단일 출처로 통합 — `_prepare_turn`(위험 2층 차단[하드블록→재분류]→intent 1회→시황 컨텍스트→messages 조립, 차단 시 세션 append 완료 후 `(blocked=True,…)` 반환), `_finalize_popups`(`with_screener_panel`→`merge_intent_panel` 순서 계약), `_tool_feedback`(콘텐츠/표시 툴 되먹임 분기·user/db 관통). 안전 로직을 한쪽만 고치는 회귀(P2 user/db 누락 이력) 재발 방지. 또한 4개 summarizer 의 반환 dict 포장은 `structured_summary.wrap_success/wrap_failure`(shape SSOT — {summary, validation_failed[, message][, report_count]}, 도메인 폴백 문구·report_count 는 extras)로 통합. 시간 헬퍼는 `infra/timeutil`(utcnow/now_iso/KST) SSOT — 각 모듈은 기존 이름(`_utcnow`/`_now_iso`) 별칭 import 로 보존(monkeypatch·재수출 하위호환).
- **스트리밍(`chat_stream`)**: SSE용 동기 제너레이터. 이벤트 `{type: "stage"|"token"|"popups"|"done"}`, stage enum = `analyze|regime|outlook|generate|summarize`(`outlook`=시장 질문의 stale 시황 동기 수집 대기, regime 다음·generate 앞·macro_view 에서만). CHAT_MODEL `stream=True`. **스트리밍 tool_calls는 델타 조각을 index별로 이어붙여 재조립**(`_accumulate_tool_calls`) — 부분 도착하는 `function.name`/`arguments`를 누적해야 완전한 팝업이 나온다. 기존 동기 `chat()`은 그대로 유지(논스트림 폴백·기존 테스트). OpenAI 실패는 1회 재시도 후 `_FALLBACK_MESSAGE`.

- **[P2] 구조화 리포트(§6.5b)**: `report_schema.py`의 `StockReport`(Pydantic)가 안전 요건을 **스키마 레벨에서 강제** — `리스크요인 min_length=1`(장밋빛 일변도 방지)·`면책고지` 필수·`종합의견 Literal["긍정적","중립","신중"]`(매수/매도 단정 라벨 원천 차단). `report.py::generate_stock_report`는 `CHAT_MODEL`로 JSON 생성 → 검증 실패 1회 재시도 → 재실패 시 **폴백**(정량요약만 + `validation_failed=True`, 부분실패 보존, §5.1). `report_store.py`가 `.cache/stock_reports.json`에 `(ticker, created_at)`·`regime_at_creation`으로 히스토리 누적(과거 평가 비교 데모). 테스트는 FakeOpenAI mock(라이브 미호출).
- **국면 = 현금비중만(build_prompt ④블록) — 진입게이트 지침 폐기(항목3)**: 국면별 종목 진입신호 지침(`single_cap`/`per_max`/`pbr_max` 게이트)은 "너무 보수적"이라 삭제됐다. ④블록은 "국면은 **현금비중만** 관리하며 개별 종목 PER/PBR 은 참고 데이터로만, 국면 상한 초과/진입 차단 커트는 없다"로 재작성. `_format_params` 는 `cash` 만 인용(3중 일관성 유지). 리포트의 `국면정합성` 은 LLM 이 국면명+권장 현금비중 스탠스 대비 '최종 적합성'을 서술(`report.py::_regime_block`).
